# Build Decisions Log

Ambiguities resolved during the V0 build, per the brief's working style: when in
doubt, choose the interpretation consistent with the product thesis
(honesty > flattery).

## Environment & stack

- **Python 3.11 venv** (not the system 3.14): the full scientific stack
  (pandas/numpy/pyarrow/matplotlib) has mature wheels for 3.11; the brief
  requires 3.11+. Homebrew `python3.11` is present on this machine and pinned
  in `Makefile`/`dev.sh`.
- **Next.js 15 / React 19** (brief said "Next.js 14"): 15 is the current stable
  App Router release; nothing in the brief depends on 14-specific behavior.
- **Charts are hand-rolled SVG** (no charting dependency): the Truth Report
  needs log-scale equity with a shaded OOS region, a visually-subordinate gross
  line, an underwater plot, and a regime timeline — all with text/table
  fallbacks (Gap #12). Owning the SVG keeps every one of those requirements
  first-class instead of fighting a library.
- **Migrations are plain SQL files** applied in order and tracked in a
  `schema_migrations` table (no Alembic). Transparent, testable, adequate for a
  single-user SQLite file; SQLAlchemy models mirror the DDL so the V1 Postgres
  swap stays mechanical.

## Engine semantics

- **Trading calendar = SPY's own index** (Gap #6 explicitly allows this instead
  of `exchange_calendars`): every run's calendar is the set of days SPY traded.
  Day-count conventions live in ONE table (`backend/dsl/conventions.py`) that
  the engine, the LLM system prompt, and the glossary all render from.
- **Stop-loss / take-profit are cut from the V0 DSL** (Gap #1, per the build
  prompt): stops on daily bars need fill-rule semantics (gap-through handling)
  the engine can't honestly provide with close-only data. The validator rejects
  them with a plain explanation. `hold_days` is defined precisely instead:
  **overlapping cohorts, equal capital per active cohort** — each rebalance day
  starts a new cohort that lives `hold_days` trading days; the portfolio splits
  capital equally across active cohorts; within a cohort, the spec's weighting
  rule applies. A golden fixture proves the semantics by hand.
- **Cost formula is Section 3's, verbatim**: `turnover[t] = 0.5 * Σ|w[t] −
  w_drifted[t−1]|`, `net[t] = gross[t] − turnover[t] × bps/10⁴`, applied on the
  execution day. Turnover is measured against drifted (not stale) weights.
- **Deterministic tie-breaking** (Gap #2): ranking sorts by (score, then ticker
  alphabetically). Identical inputs produce identical selections on every
  platform.
- **Risk-free rate**: try 13-week T-bill (^IRX) from the data layer; on any
  failure fall back to 0 **with a disclosed audit NOTE** — never silently.

## Data

- **Fixture panels double as offline data**: the frozen War-list and S&P 500
  CSVs from the original session are checked into `fixtures/` and seeded into
  the parquet cache by `make seed`, so the app (and the selection-bias audit's
  neutral-universe re-run) works with zero network access.
- **S&P 500 constituent seed list**: checked in at
  `fixtures/sp500_constituents.csv`, sourced from the Wikipedia "List of S&P
  500 companies" table (snapshot taken June 2025 during the original session).
  `scripts/refresh_sp500.py` re-scrapes it on demand. *Superseded for S&P 500
  windows from 2015 on by point-in-time membership — see "Point-in-time S&P
  500 membership" below; "mildly" survivorship biased turned out to be wrong.*
- **Snapshot format is parquet** with a SHA-256 content hash stored on the Run
  row. Re-runs replay the snapshot by default; "refresh data" is the only path
  to new numbers.

## LLM layer

- **Model: `claude-sonnet-5`** (env-overridable via `HONEST_LLM_MODEL`). The
  brief's Section 2 suggested Opus-class; the build prompt (which wins)
  specifies the current Sonnet-class model. The eval harness is the instrument
  for judging whether a model change is safe.
- **Cheaper tier is one env var, but the savings are smaller than the sticker
  price suggests.** `claude-haiku-4-5` is $1/$5 per MTok vs Sonnet 5's $3/$15,
  yet our system prompt is only ~2.4K tokens: Sonnet 5 caches prefixes ≥1024
  tokens (repeat calls bill the prompt at ~0.1×) while Haiku 4.5 needs ≥4096
  to cache at all, so Haiku never gets a cache hit here. Real per-call cost
  lands ≈$0.005 (Haiku) vs ≈$0.006–0.008 (Sonnet, cached) — both far under a
  cent. Haiku also **rejects the `effort` parameter** (400), so
  `llm.translate.supports_effort()` gates it by model prefix; switching tiers
  can never break the endpoint. If cost ever matters at volume, the highest-
  leverage move is padding the prompt past 4096 tokens with *more few-shot
  examples* — that buys caching AND accuracy at once.
- **The readback shown on the spec card is generated by Python template code
  from the validated JSON** — never by the LLM call that produced the spec
  (non-negotiable #6). The LLM's own readback, if any, is discarded.
- **Translation cache**: SQLite keyed by (prompt version, SHA-256 of input
  text). Cache hits skip the API entirely; every translation attempt is logged
  and doubles as the future eval corpus (Gap #11).

## LLM layer — translation semantics

- **Material vs immaterial parameters** (non-negotiable #5 vs the Section 1
  "assumed monthly — correct?" example): the ranking signal + lookback, the
  holding count, and the rebalance frequency are MATERIAL — the model must ask,
  never default. Benchmark (SPY), window (last 10 years), weighting (equal),
  and skip_days (0) are immaterial defaults the model may apply but must list
  as assumptions, which the spec card shows in amber for confirmation. The
  spec-confirm gate ("Run the gauntlet") still covers everything.
- **`effort: "low"`, `max_tokens: 4000`** for translation calls: Sonnet 5 runs
  adaptive thinking by default and `max_tokens` caps thinking + text together,
  so the brief's 2000 was raised to 4000; low effort keeps the spec card
  feeling instant. The eval harness is the instrument that validates this
  choice — if accuracy drops below the 90% bar, raise effort, re-run
  `make eval`.
- **"Exact-match" operationalized as subset-exact-match**: each eval case pins
  the fields the input actually determines (signal, lookback, n, direction,
  rebalance, filters, window…) and compares them exactly against the expanded
  spec; fields the input leaves open (e.g. the name string, defaulted window
  dates relative to "today") are not asserted. Ticker lists compare as sets.

## Reports & export

- **PNG/PDF export is rendered server-side with matplotlib**, so the
  disclaimer is drawn into the artifact pixels (and embedded in PNG metadata),
  not overlaid by the browser. A shared image detached from the app still
  carries the legal footer (Gap #10).
- **Verdict always uses the pessimistic cell**: net-of-costs, validation
  segment. Green requires beating SPY at 20 bps net in the holdout, with no

## Adversarial verification of the engine (M1 workflow)

An 18-agent verification workflow (a) independently recomputed both golden
fixtures from the raw CSVs + written semantics — every checkpoint matched the
engine to the exact fraction — and (b) adversarially reviewed the engine.
All confirmed findings were fixed and pinned with regression tests
(`test_engine_fixes.py`):

- inverse-vol + zero-volatility (stale-feed) ticker produced a silent all-cash
  run reported as exactly 0% — now excluded at eligibility AND disclosed.
- `return`/`daily_return`/`rsi` signals bridged data holes (halts, vendor
  gaps), making tickers eligible with fabricated momentum — signals now
  require a complete gap-free lookback (the documented rule, now enforced).
- Cohort mode's daily capital re-equalization was uncharged turnover —
  pre-trade weights are now NAV-share aggregated; the cohort golden fixture's
  Jun-7 turnover changed from 0.25320563663 to 727871/2875008 =
  0.25317181726 (re-derived by hand).
- Cohort-mode gap disclosure checked the forward-filled array (dead code) —
  now checks raw prices; conventions updated to state cohort positions carry
  to cohort expiry.
- Max drawdown ignored losses from initial capital — the peak now includes
  the day-0 stake.
- Metrics silently skipped NaN — they now refuse with an explicit error.
- The panel calendar was the union of every ticker's dates, so one spurious
  weekend row could hijack a month-end rebalance — the calendar is now
  strictly SPY's sessions (as the conventions table always said), disclosed
  when rows are dropped.
- `skip_days`/`fast`/`slow`/`lookback_days` on inapplicable signal types were
  silently ignored — now validation errors (spec fidelity: what you confirm
  is what runs).

## Audit semantics (decided empirically during M4)

- **Neutral-universe comparison uses common accrual dates only.** The
  hand-picked run and the S&P re-run can start accruing at different times
  (signal lookback meets different data histories); totals over different
  periods are not comparable. The 2× FATAL ratio is computed over the
  intersection of accrual dates.
- **A ranked strategy on a hand-picked universe can never earn green.** The
  War-list fixture exposed why the 2× rule alone is not enough: over
  2023–2026 (the AI melt-up), *identical* top-5 momentum rules on the CURRENT
  S&P 500 list returned +3405% net-5bps — more than the War list's +1905% —
  because today's index list contains exactly the stocks that mooned into it
  (SMCI, PLTR, APP, CVNA…). The "neutral" list is itself survivor-loaded, so
  a favorable ratio must never launder a hindsight universe into a green
  verdict. Rollup rule: ranked + user_watchlist ⇒ verdict capped at amber
  with the selection-bias card and a one-click S&P re-run; FATAL still fires
  when the ratio exceeds 2×.
- **Verdict rollup determinized** (Section 3 → concrete order): FATAL →
  red "not trustworthy"; holdout net-5bps trails benchmark → red; net-20bps
  (full window) trails → amber "dies at realistic costs"; no bear market →
  amber; sensitivity flip → amber; hand-picked ranked universe → amber;
  else green (rare by construction).

## Dip-buy cost-collapse reproduction (Definition of Done)

The original session's "gross win → net death" came from `reversal.py`, which
holds **today's losers for one day** on the War list and subtracts a flat
daily cost. Empirically reproduced through the hardened engine on the frozen
War panel (2022-01 → 2026-05): gross +151.4% (Sharpe 0.92) beats SPY +67.9%
(Sharpe 0.53); still ahead at 5 bps (+121%); **flips to losing at 20 bps
(+50.1%)** with ~59× annual turnover — pinned in
`test_audit.py::test_dip_buy_cost_collapse_reproduction`. (Numbers moved a
little when the adversarial-audit fixes landed — gap-free lookbacks and
NAV-share cohort turnover; the flip itself is unchanged.)
The brief's worked example #2 (5% dip filter, 5-day hold) trades ~16×/yr
under honest turnover-scaled costs and does NOT flip on the tested windows —
on 2019–2024 it never beats SPY even gross, so there is no gross win to lose;
the flat per-day cost in `reversal.py` overstated its drag, and the
turnover-scaled formula (Section 3, which wins) is gentler on slow-rolling
cohorts. Both variants ship as tests; the report shows the flip wherever it
exists.

## UI redesign — analyst workstation (post-V0)

Design system derived with the ui-ux-pro-max skill: **Data-Dense Dashboard ×
Swiss Modernism 2.0** structure on the **B2B Service** palette (navy `#0F172A`,
blue `#0369A1`, off-white `#F8FAFC`). Every text/background pair was contrast-
checked before adoption; the one weak pair (muted label on tinted fill, 4.34:1)
was darkened to `--ink-label #475569`.

- **No webfont.** The skill recommended Fira Sans/Fira Code, but this is a
  local-first tool that must render instantly and work fully offline — a
  Google Fonts dependency (or a `next/font` build-time fetch) trades that away.
  System stack + `font-variant-numeric: tabular-nums` gives the analytical feel
  with zero network cost.
- **The generated "pattern" was rejected.** `--design-system` matched a
  marketing "Real-Time / Operations Landing" with an "Exaggerated Minimalism"
  style — both contradict the brief's "first screen is the workflow, not a
  hero". Only the colour/typography/density dimensions were taken from it.
- **The audit panel is labelled "Audit note · deterministic, not
  model-generated", NOT "AI analysis".** The requested direction asked for an
  AI-analyst research note; our findings come from deterministic Python, and
  labelling them AI in a product whose thesis is honesty would be a lie in the
  chrome. The research-note *form* (What worked / What failed / Main risks /
  Suggested next tests) is implemented exactly as asked; only the attribution
  is truthful.
- **Risk badges, evidence strength, stress cells are derived, never invented**
  (`frontend/lib/insights.ts`): each maps to a real finding or metric — e.g.
  "High drawdown risk" from `max_drawdown ≤ −30%`, "Regime-sensitive" from
  `regimes.has_bear_market === false`. "Confidence" is deliberately
  *evidence strength* (sample size + regime coverage), not a model-confidence
  score, which we have no basis to report.
- **Features in the direction with no honest data source were not faked.**
  There is no per-trade log (the DSL has no trade concept) — it became a
  **rebalance log** from real `holdings` rows; there is no capital/fees/
  slippage input (costs are a fixed product-rule sweep) — the settings panel
  shows the real DSL fields instead.

## Multi-provider translator + cost bench

The translator is now provider-agnostic: `backend/llm/providers.py` holds
Anthropic / OpenAI / Gemini adapters behind one `call_model()`, and
`backend/llm/pricing.py` is the single catalogue of model IDs and prices
(fetched 2026-08-03 from each provider's own pricing page — they go stale, so
re-check before trusting a comparison).

- **Accuracy is the gate; cost only breaks ties.** `make bench` replays the
  same 30 eval cases through each candidate and reports spec accuracy, gate
  accuracy (clarify/refuse), measured $/1k runs, and p50 latency. It refuses
  to name a winner unless a model clears ≥90% spec AND 100% gate accuracy.
  This ordering is the whole point: a translator that reads "6-month" as 26
  days answers the wrong question at any price.
- **Cost is measured, not estimated.** Every adapter returns real token counts
  including cached-prefix tokens, and `ModelSpec.cost()` applies the provider's
  cached-input rate. This matters because prompt caching, not list price,
  dominates: our ~2.4K-token system prompt caches on Sonnet 5 (≥1024 min) and
  on OpenAI, but NOT on Haiku 4.5 (≥4096 min), and Gemini has no equivalent
  discount in the catalogue.
- **A JSON-mode fallback exists per provider.** If a provider's strict
  structured-output mode rejects our schema (nested unions + `extra=forbid`
  are a common tripwire), the adapter retries in JSON mode and validates with
  Pydantic ourselves, recording `path="json_fallback"`. Without this the bench
  would score SDK schema quirks as "this model can't translate strategies".
  The deterministic validator still gates everything downstream either way.
- **Models are skipped, never silently dropped,** when their key is absent —
  the table says `skipped · no OPENAI_API_KEY`.
- **Untested against live endpoints.** No provider key exists on this machine,
  so the adapters' wire behaviour is unverified; the plumbing, usage
  accounting, cost math, fallback path, and effort gate are covered by 18
  mocked tests (`test_providers.py`).

## Landing page redesign — "Broadsheet" (2026-08-03)

**Ambiguity:** the user rejected the previous landing page as "very ai sloppy"
and asked for a premium, professionally-designed feel. Three directions were
offered; **A · Broadsheet** was chosen.

**Resolution — what "not AI-generated" was defined as, in measurements:**

| Signal | Before | After |
|---|---|---|
| Distinct font sizes | 17 (11 of them between 10.5–15px) | 6 |
| Type scale range | 4.2× | 6.9× (11px → 76px) |
| Bordered boxes | 15 | 7 |
| Border radii | 3 | 1 |
| Box shadows | 4 | 0 |
| Icon-card grids | 6 identical cards | 0 |
| Real product screenshots | 0 | 1 |
| WCAG failures | — | 0 of 118 text nodes |

**Decisions and why:**

1. **Fonts are scoped to `/landing`, not global.** Montserrat (display),
   Newsreader (serif reading voice) and Inter (UI) load via `next/font/google`
   inside `app/landing/layout.tsx`. The app itself keeps the system stack so it
   still renders instantly and works fully offline — a webfont on the workbench
   would trade a real local-first property for decoration.

2. **The six-step ramp is enforced by tokens** (`--t-micro/small/body/lede/
   head/hero`). Fluid `clamp()` rules interpolate *between two existing steps*
   rather than inventing a seventh size, so the count holds at every viewport.

3. **The six icon-cards became six numbered editorial rows.** A grid of
   identical icon cards was the strongest generated-looking signal on the page.
   Rules and whitespace carry the structure instead.

4. **The screenshot is a genuine export**, generated from run `rep_2c6332f417`
   via `/api/report/{id}/export.png`. It shows an *amber* verdict, not a
   flattering one — consistent with the product thesis. Its benchmark row and
   disclaimer are baked into the PNG, so a social screenshot carries them.
   The plate crops to ~540px with a fade because the export is 4:5 portrait and
   would otherwise swamp the page.

5. **Oxblood `#7A2E2E` over the default SaaS blue.** The palette should suit a
   tool whose job is to disagree with you. All nine pairs verified ≥4.99:1.

**Bugs found and fixed during the pass:**
- `::first-letter` was scoped to an inline `<span>`, where it does not apply —
  the drop cap silently did not render. Moved to the block `<p>`.
- `.bs-term li` used `display:flex`, which promoted inline `<strong>` to a
  sibling flex item and broke the Pro tier's first bullet across a false
  column. Changed to normal inline flow with an absolutely-positioned mark.
- The masthead nav did not wrap below 760px and overflowed the right edge.

**Unchanged on purpose:** no backend, DSL, engine or test changes. The audit,
the unconditional benchmark, and the disclaimer on every report and export are
untouched — 120 passed, 1 skipped after the pass, and the production build is
clean.

**Figma:** the connector authenticates, but the seat is **View** on a
Starter-tier team, i.e. read-only — it can inspect files, not author them. Not
used here: with no pre-existing Figma file, designing there and re-implementing
in code is strictly longer than iterating in code against measured targets.

## The overflow was in the export itself (2026-08-03, follow-up)

**Correction of my own diagnosis.** The user reported the overflow twice; the
first fix (the landing plate's viewport-dependent crop) was real but was not
what they were pointing at. The actual defect was **inside the exported PNG**:
matplotlib's `wrap=True` wraps text at the *figure* boundary, not at the box
the text sits in, so the verdict sub-text ran through the amber banner's right
border before wrapping — in every export, on every surface that displayed one.
No frontend change could ever have fixed it.

**Fix (`backend/export.py`):** `_wrap_to()` overrides a text's
`_get_wrap_line_width` to the banner's inner width (private matplotlib hook,
stable for years; the regression test pins it by measuring rendered extents).
Headline and sub are now top-anchored so extra wrapped lines grow downward
into known-clear space; the disclaimer footer wraps at 88% figure width so it
keeps side margins. PNG and PDF share the path.

**Proof:** new `test_verdict_text_stays_inside_banner` renders all three
verdict colors with long headlines and a 180-char sub and asserts, in pixels:
no right-border crossing, no bottom crossing, no headline/sub collision.
Pixel scan of the re-exported sample: 0 text pixels in the 30px band inside
the border (was: text touching it). Landing crop row 920 still 0.0% busy.
Suite: 121 passed, 1 skipped.

**Lesson recorded:** when a user says "still not fixed", re-derive what they
are looking at from their screenshot's pixels before assuming the prior
diagnosis was merely incomplete — the defect lived one layer deeper than
where I fixed it.

## Phase 2 — one product, two densities (2026-08-03)

The landing page was premium and the app behind it was still blue-on-slate
SaaS. A visitor clicking "Open the app" changed products mid-click.

**Approach: retheme the token layer, not the pages.** Every page already used
semantic classes (`.panel`, `.metric`, `.verdict`, `.finding`, `.chip`), so
rewriting `:root` plus ~65 targeted structural rules transformed all six pages
at once without touching a line of page logic. Far lower risk than rewriting
six components, and it makes future theme changes one-file changes.

**What carried over from Broadsheet:** warm paper `#FAF9F7`, ink `#1A1815`,
oxblood `#7A2E2E` as the only accent, one radius (2px), zero shadows, rules
instead of boxes. **What deliberately did NOT:** the 76px editorial scale. The
workstation is a dense analyst tool; it gets its own ramp (11/12/13/15/19/28)
in the same families. One system, two densities — hence `--display`,
`--serif`, `--sans` shared via `lib/fonts.ts` and loaded once in the root
layout.

Fonts now load app-wide. `next/font` self-hosts at build time, so the
local-first/offline promise is unaffected — the earlier "scoped to /landing"
decision was about avoiding a runtime dependency that self-hosting removes.

**Notable per-page changes**
- Sidebar/topbar sit on paper; the current nav item is marked with an inset
  oxblood rule instead of a filled blue pill.
- Metric cards lost their boxes: a 2px ink rule over a 28px Montserrat figure,
  newspaper-table style.
- Verdict banners: flat semantic band + thick left rule, no gradients.
- Glossary was a stack of ~12 identical bordered cards — the single strongest
  "generated" tell. Now ruled reference entries with serif prose.
- Badges/pills/chips squared (999px radius is a SaaS chip signature).
- Regime legend swatches were still the old bright palette while the bars had
  been retoned — they were hardcoded in `charts.tsx` and now match.
- Equity line and neutral sparklines were oxblood, which reads as "loss" on a
  +3553% gain; now ink, matching the landing demo's grammar.

**Bugs found while doing it**
1. `/health` reported `llm_configured` from `anthropic_api_key` ALONE — it
   predated multi-provider support, so a working OpenAI setup showed
   "Translation: no API key" in the sidebar while translating fine. Now asks
   the provider that owns `settings.llm_model`, and returns the model name.
2. `test_requires_api_key` blanked only the Anthropic key, so it silently
   stopped testing anything the moment a real `OPENAI_API_KEY` existed. Now
   blanks every provider.
3. The five result tabs overflowed a 414px phone by 2px, putting a horizontal
   scrollbar on every mobile view. The tab bar now scrolls internally.

**Measured after (report page, all five tabs):** 7 type sizes, one radius
(2px), zero shadows, zero WCAG failures, no horizontal overflow at 414px.
121 passed, 1 skipped; production build clean.

## Phase 3 + beyond: backup, storage, and deploy prep (2026-08-03)

**Phase 3 — private GitHub backup.** Pushed to
`himagna16/honest-backtester` (**private**). Pre-flight checks, all clean:
`.env` untracked and gitignored, zero `sk-proj-`/`sk-ant-`/`AIza…` matches in
the entire history *and* the working tree, and `data/` excluded — it holds real
waitlist email addresses, which should not sit in a repo even a private one.

**Content-addressed snapshots (the SAAS_PLAN "fix before launch" item).**
Panel bytes now live once at `data/panels/<sha256>.parquet` and are shared by
every run whose panel hashes identically; run directories keep only
`panel_meta.json` pointing at the blob. Reproducibility is untouched — the
content hash *is* the identity of the bytes, and the integrity check still
raises on mismatch.

- Blobs are written to a temp name and `replace()`d, so a crash mid-write can

## gpt-5-nano returned empty output ("model returned non-JSON") (2026-08-03)

**Symptom:** running a strategy sometimes failed with
`model returned non-JSON: Expecting value: line 1 column 1 (char 0)`.

**Root cause — reasoning tokens, not a JSON bug.** gpt-5-nano is a reasoning
model: hidden reasoning tokens are drawn from `max_completion_tokens` BEFORE any
visible output. Measured on the real translator prompt, a single translation
spent ~2,000–2,600 tokens reasoning. Against the 4,000 ceiling that leaves a
razor-thin margin; a slightly harder input pushes reasoning over the limit,
`finish_reason` becomes `length`, and content is empty. The SDK's `.parse()`
then raised, the code fell through to the JSON-mode fallback, that call ran out
of budget the same way, and `json.loads("")` produced the cryptic error. It was
intermittent precisely because it depended on how much the model happened to
reason for a given input.

**Fix:** send `reasoning_effort="minimal"` for gpt-5* models (gated by prefix;
older gpt-4.1-nano rejects the parameter). Translation is extraction, not
problem-solving. Measured effect: reasoning tokens 2,048 → 0, completion tokens
2,138 → 153 (~14x cheaper output), still a complete and correct spec. Applied to
both the native `.parse()` and the JSON-mode fallback.

**Defense in depth:** both paths now detect empty content / `finish_reason
== "length"` and raise a clear `token_limit` error naming the cause, instead of
letting a blank string reach `json.loads`.

**Verified:** 5/5 fresh translations succeed; harder inputs map correctly
(bottom-10 Nasdaq-100 over 63 days weekly; a quarterly-rebalance request
correctly returns needs_clarification rather than guessing). 3 new provider
tests (effort gating on/off, clear empty-content error). 126 passed, 1 skipped.

# Institutional-grade rebuild (Sept 2026)

Four adversarial workflow rounds against the engine, metrics, significance,
validation and attribution modules, plus the pipeline integration. Test count
**131 → 483 passed, 1 skipped**.

Every round had the same structure: a builder that owned a disjoint set of
files, then a FRESH reviewer given a different lens, required to reproduce the
original counter-example and to prove each new test dies under a stated mutant.
That structure is the reason the numbers below exist at all — four of five
modules came back SERIOUS-ISSUES after the first build round, and the defects
were found by running counter-examples, not by reading code.

## The single most important lesson: over-scoped guards

**Three separate regressions in this effort were introduced by a fix, not by
the original defect, and all three had the same shape: a guard applied one
level too high.**

1. `INVERSE_VOL_FLOOR_ANNUAL = 0.05` was calibrated ~250× above the threat it
   existed to stop. It bound on **AGG — this project's own 60/40 bond leg — on
   72.7% of days**, distorting target weights by up to 18.5 percentage points,
   and emitted "check the feed: AGG (2.02%)" about a perfectly healthy bond
   ETF. A false data finding is a house-rule violation. Only 4 of 504 S&P names
   ever dip below 5%: the floor was inert where it was aimed and decisive where
   it was not. Recalibrated to 0.005, pinned from BOTH sides (must not bind on
   AGG; must bind on a near-frozen feed).
2. `_check_prices_usable` scanned the ENTIRE panel instead of the simulated
   window, so one vendor zero anywhere in ~500 columns across the full fetched
   history refused a run whose own window was clean. Scoped to the lead-in +
   window actually read; refusal semantics kept.
3. `alpha_testable` was folded INTO `alpha_significant`, which several call
   sites consume. That silenced the fabricated pass and simultaneously created
   a fabricated *refutation*: a strategy with a real +5.0%/yr premium was told
   it added nothing, in a message carrying a 15-digit t-statistic.

**Rule going forward: gate at the site that RENDERS the claim, not at a shared
predicate.** A false refutation is worse than a false pass — it misleads in the
other direction while looking rigorous.

## Tests that cannot fail

Mutation testing found **16** across the modules. The worst: deleting the
Bonferroni multiple-testing haircut (`p_bonf = min(1, attempts * p_raw)` →
`min(1, p_raw)`) left **all 50 attribution tests green**, while
multiple-testing is a headline honesty claim of this product.

A test that shares a constant with the implementation is not evidence. The
purge module's leak invariant pinned `REACH = 21` *equal to*
`STALENESS_LOOKBACK_DAYS`, so the staleness term was permanently masked and
zero of the 8 engine-level leak tests could detect its removal. The module also
*claimed in three comments* that those tests were the evidence. In a module
whose thesis is "a test that restates the formula is not evidence", an
overclaim about which tests ARE evidence is the same defect one level up.

## Corrected numbers

- **60/40 benchmark** silently inherited the new 1-day execution lag while
  SPY/QQQ still used raw `pct_change`, so the benchmarks were mutually
  inconsistent. All benchmarks are now lag-0 (a passive buy-and-hold benchmark
  has no signal, so no fill lag applies). Verified against a from-scratch
  share-count simulator (max abs diff 4.4e-16) and a hand pin
  `0.6·r_SPY + 0.4·r_AGG = 0.00120004`.
- **VaR/CVaR annualization** was wrong by ~1.7×: √252-scaling a *quantile* is
  invalid. A true 1-year 95% VaR near −16.3% was reported at ~1.7× that.
- **`breakeven_cost_bps`** was 2× too high — it divided by one-way turnover
  after the engine moved to charging per dollar of traded notional
  (= 2 × turnover). It now imports the convention rather than re-deriving it.
- **The purge leaked.** `REBALANCE_CARRY_DAYS` understated the true maximum
  gap, RSI's Wilder smoothing is IIR (no finite reach — a perturbation at t−15
  is LARGER than at the claimed maximum), and `execution_lag_days` was ignored.
- **Staleness false-positive flicker** 32.1% → 9.1%, re-derived from the exact
  binomial; a genuinely dead feed is still caught with probability 1.0.
- **A significant NEGATIVE alpha reported as PASS** — every branch keyed on
  `abs(t)`.
- **`calendar_rebalance_carry`'s tail term was deleted as "dead code" and was
  not.** On a tz-aware calendar `rebalance_signal_dates` drops the timezone, so
  `get_indexer` returns −1 for every signal date; the tail term was the only
  thing that noticed, converting a loud `SplitError` into a silent 22-bar-short
  purge (255 vs 277). It now refuses with
  `reason="signal_dates_not_on_calendar"`. **This deletion was instructed on a
  wrong premise** — the round-2 reviewer claimed the branch was unreachable and
  its comment impossible; the comment actually read "Normally 0 … kept so a
  clipped calendar cannot surprise us", which was correct.

## Where agents were right to refuse

Four reviewer-prescribed fixes were rejected with measurements, and the
rejections were correct:

- The suggested position cap `min(0.25, 4/n)` is **infeasible**: for k ≤ 4 it
  demands every weight sit below 1/k while summing to 1. Shipped
  `max(0.25, 2/k)`.
- A proposed effective-sample-size gate measured **worse** coverage than no
  gate (0.915 → 0.838), because a data-conditioned gate admits exactly the
  replications whose long-run variance came out small.
- A suggested degeneracy tolerance was **six orders of magnitude** below the
  threshold it replaced.
- The prescribed staleness reach of 20 bars is one short: the diff at t−20
  consumes the closes at t−21 *and* t−20, so the earliest price a verdict at t
  touches is t−21. Measured: bumping bar b flips bars b…b+21 inclusive.

## Pipeline integration

- **The risk-free rate is a PATH, not a window average.** It is used three ways
  that must agree — cash accrues it, metrics subtract it, the Sharpe hurdle
  quotes it. `conventions.py` had been honestly disclosing that the hurdle and
  the cash yield disagreed; they no longer do. A gap at the window start takes
  0% and is disclosed rather than carrying a later rate backward onto an
  earlier day (that would let the future set an earlier day's hurdle).
- **Trial ledger** (migration `003_trial_ledger.sql`). The Deflated Sharpe
  prices the search, and the luck threshold scales with **√V[{SRₙ}]** — the
  *spread* of prior trial Sharpes, which `attempt_counters` never stored. Every
  completed run now records its Sharpe, keyed by `run_id` so a replay cannot
  inflate its own haircut, and the ledger is read BEFORE the run is appended so
  a strategy never has to clear a bar it raised itself.
  - A **one-entry ledger is not a spread of zero**. Passing it through raised
    `ValueError` and took down the whole run; treating it as variance 0 would
    be worse, claiming the search was free. It refuses, and says so.
  - At `n_trials = 1` the DSR reduces to the PSR and needs no trial variance,
    so a single-attempt run is computable either way — any test of the ledger
    path must use ≥ 2 attempts or it hides the bug.
- **Holdout purge disclosure.** The 70/30 split is a plain date cut. The report
  now states how far a training bar reaches past it, itemized. On a low-vol
  quarterly S&P spec: 87 sessions (signal 20 · staleness 21 · carry 64 · lag 1
  · cost 1). The verdict's split was deliberately NOT moved — that would change
  every historical number — but the overlap is a data problem, so it surfaces.
- **A purge that cannot be measured surfaces as a warning**, not as silence.
  `SplitError` carries a machine-readable reason precisely so a caller can turn
  the refusal into a Finding; the first integration swallowed it and dropped
  the disclosure entirely, reporting the most dangerous case the most quietly.

## A fourth guard-shape defect: dust over dust

The "over-scoped guard" lesson above needs a companion, found by the round-5
reviewer after that section was written. Three of the four bad guards in this
effort were too HIGH. This one is too NARROW, and it is the most dangerous
because it survives every test aimed at the family it was built for.

**Every degeneracy guard in `attribution.py` keys on
`resid_var_share = SSR / SST`, a RATIO.** It catches a vanishing NUMERATOR (an
exact factor combination). It is blind when the DENOMINATOR collapses: if the
dependent variable has no variation of its own, SST is rounding dust too, the
ratio comes out **above 1**, `alpha_testable` is True, and every "gated"
verdict fires.

Reachable from the product using only committed fixtures — a strategy whose
filter never qualifies returns 0.0 every day (the engine returns 0, not rf,
when no rate is supplied), and the fixture rf is **flat at 0.0002 for 793
consecutive sessions**, so excess = −rf is a nonzero constant. Reproduced by
hand on the live tree:

| finding | severity | what the reader is told |
|---|---|---|
| `factor_alpha` | **warning** | "alpha is −5.0%/yr with a HAC t-statistic of −372352520723111.69 — significantly BELOW zero" |
| `factor_spanning` | **warning** | "intercept is −5.0%/yr … beta 0.00 and R² **−335126%**" |
| `factor_reliability` | **pass** | "the regression is well-posed and the loadings are interpretable" |

Three confident findings, all fabricated, one of them a PASS.

**Two free tells were available and neither was checked.** For OLS with an
intercept, `SSR <= SST` is an identity — so `resid_var_share > 1` (measured
3507) and `r2 < 0` (measured −3506.51) are each *arithmetically impossible*.
Either alone would have caught it. The lesson generalizes: when a quantity has
an algebraic bound, assert the bound; an impossible value is the cheapest
degeneracy detector there is.

**The grid test could not have caught it, and could not catch its next
relative.** `DEGENERATE_GRID` sweeps `rf + c*mkt_rf` — varying the coefficient
drives only the NUMERATOR to dust, so SST stays ~1.0 by construction. Its
non-vacuity assertion was one-sided (`resid_var_share <= FLOOR`) and satisfied
by construction on that family. A degeneracy sweep needs **both axes**.

The same `dust / dust` hole exists in `significance.py`'s `newey_west_tstat`:
`tstat = mean / se if se > 0 else nan` cannot catch dust divided by dust, and
feeds both a verdict keyed on `abs(t) >= 2.0` and a formatted t in reader-facing
prose.

**Open at the time of writing** — round 6 is addressing both. The entry above
describing this rebuild should be read as the state after round 4; rounds 5 and
6 are recorded here.

## The degeneracy policy (generalized after seven rounds)

Seven rounds each fixed a named degeneracy case and left a sibling. The
siblings were not bad luck — they were the same defect at a different **level**
or a different **site**. The instances:

| round | where the guard was | what escaped |
|---|---|---|
| 3 | a 250×-miscalibrated absolute floor | bound on AGG, a real asset class, 72.7% of days |
| 3 | a whole-panel scan | refused runs whose own window was clean |
| 4 | folded into a shared predicate | flipped a fabricated pass into a fabricated refutation |
| 5 | a ratio `SSR/SST` | blind to a collapsing denominator (R² = −335126%) |
| 6 | the entry point only | the renderer fabricated while the entry refused |
| 6 | whole-series | one bootstrap resample collapsed (`+1.99e14%`) |

**The policy, which is what should be maintained going forward:**

1. **One named degeneracy predicate per module**, checking BOTH the relative
   share AND the absolute scale. A pure ratio is blind to a collapsing
   denominator. A pure absolute floor mis-calibrates. You need both, and they
   must not disagree — in `significance.py` they disagreed by nine orders of
   magnitude, and the looser one was the site that rendered the claim.
2. **Applied at every site that RENDERS a claim**, not only at the bundled
   entry point. A gate at the entry that is missing at the renderer means the
   entry refuses while the renderer fabricates.
3. **Applied at every LEVEL the arithmetic happens**, including inside a
   resampling loop. A whole-series guard cannot see one resample collapse:
   `se_b > 0` passed on `se_b = 5.089e-21`, and ~14% dust pivots turned a
   "loses" verdict into "ties_within_noise" while printing an upper bound of
   +19,879,096,992,716,836.00% into a finding message.
4. **Where a quantity has an ALGEBRAIC BOUND, assert the bound.** `SSR <= SST`
   is an identity for OLS with an intercept, so `resid_var_share > 1` and
   `r2 < 0` are impossible — the cheapest degeneracy detector available, and it
   needs no calibration at all.

A corollary for tests: a degeneracy sweep must vary **both axes**. The original
grid swept `rf + c*mkt_rf`, which drives only the numerator to dust; SST stayed
~1.0 by construction, so the whole family was structurally invisible to it.

### Mutation-testing method note

A mutation mirror built with **symlinks reports every mutant as surviving**,
because `backend/tests/conftest.py` calls `Path(__file__).resolve()` and a
symlinked tests directory resolves back to the live module. Use a real copy,
and prove the mirror is sensitive with a deliberate always-fail mutation before
trusting any result. One reviewer caught this in its own method and rebuilt —
which is the only reason its 21/21 kill count means anything.
